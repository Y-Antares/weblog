    Memos & Timeline

    提醒：自己搭建memos需要域名和服务器，谨慎开启。

    1. 首先安装docker，参考Windows 环境下安装 Docker 的详细教程（超详细图文）_docker安装windows-CSDN博客 [2]。当然，对于我这种折腾过太多次的老油条，直接在Docker Desktop: The #1 Containerization Tool for Developers | Docker [3]下载AMD64版，安装，GITHUB登录就可以了。

    2. 接下来在CMD中用DOCKER安装：docker run -d --name memos -p 5230:5230 -v ~/.memos/:/var/opt/memos neosmemo/memos:latest

    3. 访问 http://localhost:5230/

    4. 注册MEMOS。自己的localhost，自己当然是管理员。

    5. 部署MEMOS。需要一个服务器，这里选择clawcloud的最低等级VPS service：请稍候… [4]。教程见：操作指南 | ClawCloud文档概览 | ClawCloud文档 [5]

      1. 创建好VPS后，SSH登录到VPS。
      2. 输入密码后，安装DOCKER环境，进行MEMOS部署。参考：搭建开源、轻量级笔记服务 Memos - 兔哥博客 [6]
      3. API地址：https://memos.yourdomain.com/api/v1/memo?creatorId=1&rowStatus=NORMAL&limit=10
      4. 把API地址加到timeline插件或是页面中：

    侧边栏小组件，通过读取本地Markdown文件真实的Git提交记录，展示文章版本演进历史。

    需要添加/更改的文件：

    1. scripts\git-history.js 拦截Hexo的文章渲染过程，调用本地底层的Git进程抓取历史记录并将其注入为可用的页面变量。

    2. themes\hexo-theme-stellar\layout_partial\widgets\git-history.ejs 构建出时间树组件的HTML结构骨架。

    自动生成参考文献

    效果：

    正文里只写普通链接：Stellar [7]
    发布后自动变成：Stellar[1]
    文末自动生成参考文献：
    [1] Stellar
    [2] Hexo

    实现思路

    Stellar 原生支持 frontmatter.references，但不会自动从正文提取引用，也不会自动给正文链接加角标。
    所以做法是：

    1. 在 Hexo 渲染前扫描正文里的 Markdown 链接

    2. 自动为每个链接分配编号

    3. 在正文链接后插入上角标[n]

    4. 同时把这些链接写入 references，让 Stellar 在文末统一渲染参考文献列表

    需要修改的文件

    1. 新增渲染过滤器文件：scripts/post-references.js，扫描正文里的 [文本](链接) <sup class="post-ref"><a href="#reference-8" id="reference-link-8" aria-label="参考文献 8">[8]</a></sup>，自动生成编号，相同链接复用同一个编号；忽略图片 ![alt](src)，把 references 自动写回文章数据。

    2. 修改 Stellar 文末参考区模板文件：article_footer.ejs，把原本的参考列表改成有序列表 <ol>，为每条参考文献加锚点 id，让正文角标可以跳转到文末对应条目

    3. 增加角标样式文件：themes/hexo-theme-stellar/source/css/custom.styl，设置上角标字号、位置、间距，调整文末参考列表样式，避免跳转后文末条目被顶部遮住。

    「图书馆」页面

    「图书馆」

    目标：
    在 Hexo 博客中创建一个 yoursite.com/library/ 页面。这个页面会自动抓取所有“读罢有感”分类下的文章，并以精美卡片的形式（包含封面、评分、作者、短评、分类标签）按阅读完成时间倒序排列。

    优点：

    • 全自动： 只需在 _posts 目录中按格式写一篇新书评，这个页面会自动更新。

    • 可靠： 不使用易出错的 tag 插件或 EJS 页面渲染，而是使用 Hexo 的 generator。它保证在所有文章被加载完毕后才执行。
